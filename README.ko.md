# Prosona

> 메타인지 기반 멀티 페르소나 서비스 기획 루프. 한 번 인터뷰하고, 그 다음부터는 AI가 굴린다.

## 무엇인가

기획자의 **판단 원칙**을 한 번 추출해 파일로 고정하고, 그 뒤로는 서비스 기획 루프 — 브리프 → 유저 페르소나 → 사용자 여정 → 레퍼런스 → 화면 설계 → QA — 를 AI가 단계별로 혼자 진행한다. 사람은 **단계 경계 4곳에서만** 승인한다.

## 왜 만들었나

AI와 화면 설계를 하다 보면 두 가지가 반복된다.

- **반복 문답 피로** — 같은 전제·취향·제약을 매 세션 다시 설명한다.
- **컨텍스트 누적 품질 저하** — 대화가 길어질수록 앞서 정한 정책을 잊고, 용어가 흔들리고, 이전 화면과 모순되는 플로우가 나온다.

Prosona는 앞의 문제를 **페르소나 파일 고정**으로, 뒤의 문제를 **페이즈별 컨텍스트 격리 + 디스크 상태**로 푼다.

## 루프

```
  00 interview   메타인지 인터뷰 → .prosona/planner-persona.md   (기획자당 1회)
        │
        ▼
  10 frame       브리프 + 유저 페르소나            [GATE 1]
  30 journey     페르소나별 사용자 여정            [GATE 2]
  40 reference   Mobbin 동일 도메인 레퍼런스
  50 screens     화면 설계 (여정 × 레퍼런스)       [GATE 3]
  60 review      가상 유저 페르소나 QA             [GATE 4]
        └─ 불합격 → 50으로 루프백 (최대 2회)
  90 handoff     최종 패키징
```

## 게이트 4개

게이트 **사이**에서 AI는 질문하지 않는다. 모호하면 가정을 명시하고 진행한 뒤 게이트에서 올린다. 각 게이트에서 AI는 산출물 요약과 함께 **자기가 내린 결정 3개와 그 근거**를 제시하고 멈춘다.

| 게이트 | 무엇을 승인하는가 | 왜 사람이 필요한가 |
|---|---|---|
| GATE 1 | 브리프 + 유저 페르소나 | 방향이 틀리면 이후 전부가 무의미 |
| GATE 2 | 사용자 여정 | 여정 구조는 되돌리기 비용이 큼 |
| GATE 3 | 화면 설계 | 산출물의 본체 |
| GATE 4 | QA 결과 | 검증은 위임 대상이 아님 |

`ultra` 모드는 GATE 2·3을 생략하지만 **GATE 1과 GATE 4는 어떤 모드에서도 제거되지 않는다.** 방향과 검증은 사람의 몫이다.

## 강도

```bash
/prosona lite    # 질문 많음, 단계마다 중간 확인
/prosona full    # 기본
/prosona ultra   # 기존 페르소나 재사용, 게이트 2개만
```
